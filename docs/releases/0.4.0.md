# z80-python 0.4.0 (in development)

Version 0.4.0 turns the reference core into a conformance reference for
cores in other languages, and makes the two properties that give it that
standing, timing correctness and readability, mechanically enforced.

## Conformance kit

- Add `z80_python.conformance`: versioned JSON manifests that fully determine a
  run (memory, initial state, host profile, lifecycle events, stop rule), one
  shared `ConformanceHost` with `flat` and `cpm-minimal` profiles, lazy
  reference traces, lockstep diff against an external trace, and a
  `python -m z80_python.conformance trace|diff` command line.
- Document the trace format as a public contract in `docs/trace-schema.md`.
  External producers may omit disassembly text; the reader derives it.
- Add `docs/conformance.md`: what must match, the host contract, and the
  certification ladder with the claim each step earns.
- Ship example manifests with committed reference traces under
  `examples/conformance/`, guarded by a test.

## Instruction core

- Runs of DD/FD prefixes and DD/FD before ED now execute as on hardware: each
  stray prefix is a 4-T-state M1 that increments R, the last prefix decides
  IX or IY, an ED after a prefix runs the ED instruction unchanged, and no
  interrupt is accepted inside the run. Previously these sequences raised
  `NotImplementedError`. The disassembler decodes them the same way. The rule
  is Young's (*The Undocumented Z80 Documented* 3.7, 6.1, chapter 5) and is
  the only core behavior without a hardware-captured vector; `docs/validation.md`
  says so. `tests/test_prefix_sequences.py` and
  `examples/conformance/prefix-sequences.json` pin it.

## Validation

- The SingleStepTests gate now compares `step()`'s T-state total with each
  case's `cycles` array, so timing is certified by the same 1,604,000 cases
  as state.
- `scripts/fetch_z80test.py` places the programs where the suite looks for
  them; previously the documented command silently skipped.
- Add FUSE 1.6.0's Z80 core test set as a fourth oracle
  (`scripts/fetch_fuse_tests.py`, `validation/fuse_runner.py`,
  `tests/test_fuse_suite.py`): 1,350 of 1,356 emulator-derived cases agree,
  and the six divergences are pinned as strict expected failures, each
  explained by the hardware-derived source the core follows instead.
- Full certification of the core under both CPython and PyPy is recorded in
  `docs/validation.md` with the commit hash and all external suites.

## Readability

- Every opcode handler's docstring starts with its Zilog mnemonic and lives in
  the module that owns that mnemonic group; `tests/test_readability.py`
  enforces both with `ast`.
- Every undocumented flag, WZ/MEMPTR, Q, and refresh-register effect carries a
  comment on the line that encodes it stating the hardware reason.
- Add `docs/start-here.md`, a primer for readers new to the Z80, and rewrite
  `docs/z80-undocumented-behavior.md` mechanism-first.

## Compatibility

- No certified instruction semantics changed: every sequence the 1,604,000
  vectors, ZEXDOC/ZEXALL, and z80test cover behaves exactly as before. The
  only change is to prefix runs, which previously raised.
- Tests import `z80_python` directly; the `z80` alias in `conftest.py` is
  removed.
- `z80_python.conformance` is public API under the semantic-versioning policy.
