# z80-python 0.2.0

Version 0.2.0 turns the validated instruction core into a stronger reference and
development component while preserving its dependency-free execution path.

## Processor lifecycle

- Add host-controlled, level-sensitive RESET with explicit request, clear, and
  pending APIs.
- Define RESET priority, 3-T-state boundary behavior, preserved state, HALT exit,
  and interaction with pending interrupt requests.
- Retain the existing maskable interrupt, NMI, EI-delay, RETN, and HALT contracts.

## CPU state

- Add immutable, validated `CPUState` values.
- Add side-effect-free `capture_state()` and host-independent `restore_state()`.
- Include all execution-relevant processor-owned state while explicitly excluding
  memory, devices, scheduling, and other machine-owned state.

## Disassembly

- Add immutable structured `Instruction` values.
- Add side-effect-free `disassemble()` and `disassemble_bytes()` utilities.
- Cover every base, CB, ED, DD, FD, DDCB, and FDCB form supported by the core,
  including undocumented indexed destination forms.
- Require an explicit safe reader instead of silently invoking mapped device reads.

## Debugging

- Add `DebugSession` for bounded execution, execute breakpoints, lifecycle-aware
  records, instruction/T-state totals, and bounded history.
- Add explicit `BoundaryKind`, `StopReason`, `StepRecord`, and `RunResult` values.
- Add `CommandDebugger`, a portable text-stream frontend for registers, stepping,
  bounded runs, breakpoints, disassembly, memory display, and history.
- Keep all debugging control outside `Z80CPU.step()` so normal execution has no
  callback or history overhead.

## Compatibility and dependencies

- Existing `Z80CPU` hosts remain source-compatible.
- The base package continues to have no runtime dependencies.
- CPU-only restoration remains explicitly distinct from whole-machine save states
  and rewind.
